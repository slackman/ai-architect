## Архитектура

```mermaid
flowchart TB
    U["Пользователь"] --> E["CDN / Edge<br/>Публичные файлы, TLS и фильтрация трафика"]
    E --> G["API Gateway<br/>Проверка токена, маршрутизация и лимиты"]
    G --> A["API-поды + HPA<br/>Проверка кэша и приём задач"]
    A -->|"Вопрос, параметры и область доступа"| C[("Redis<br/>Семантический кэш<br/>Ответы и векторы вопросов")]
    C -->|"Запись кэша"| A
    A -->|"Есть ответ и подтверждены права"| HIT["Ответ API: HTTP 200<br/>Ответ с источниками"]
    A -->|"Нет подходящей записи"| PG[("PostgreSQL<br/>Задачи и события для отправки")]
    PG -->|"После сохранения"| ACK["Ответ API: HTTP 202<br/>Задача сохранена, task_id"]
    PG --> P["Обработчик отправки событий"]
    P --> Q[("RabbitMQ<br/>Очередь вопросов<br/>Очередь обработки документов")]
    subgraph POOLS["Независимые пулы обработчиков"]
        W["Пул вопросов + vLLM<br/>Поиск источников и генерация"]
        DOC["Пул обработки документов<br/>Извлечение и индексация"]
    end
    Q -->|"Вопросы"| W
    Q -->|"Обработка документов"| DOC
    D[("Qdrant, Neo4j и PostgreSQL<br/>Источники и права доступа")] --> W
    Q -.->|"Метрики каждой очереди"| K["KEDA"]
    K -.->|"Число подов каждого пула"| POOLS
    W --> V["Проверка ответа<br/>Цитаты и актуальный доступ"]
    V --> R[("PostgreSQL<br/>Результаты и статусы задач")]
    DOC -->|"Статус и результат обработки документа"| R
    R -->|"Результат"| F["API результата<br/>Проверка пользователя<br/>и доступа к документам"]
    G -->|"GET /tasks/{task_id}"| F
    R -->|"Сохранение ответа на вопрос"| C
```

Сплошные стрелки показывают движение запросов и данных, пунктирные – управление масштабированием. Обозначения PostgreSQL относятся к одному логическому хранилищу задач, результатов, текстов и прав доступа. HTTP 200 и HTTP 202 формирует API. Стрелка от PostgreSQL к HTTP 202 обозначает условие возврата ответа: задача уже сохранена.

Клиент обращается к API результата через API Gateway по `task_id`. Пулы вопросов и обработки документов используют свои очереди и масштабируются независимо. На схеме показаны приём задач и получение результатов. Чтение оригиналов документов и запись индексов внутри обработки документов опущены. В кэш добавляются только проверенные ответы на вопросы. Подтверждение обработки сообщения отправляется после сохранения результата. Обработка сбоев описана в README.
