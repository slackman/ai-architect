# ADR-003: Qdrant и граф связей Neo4j

## Контекст

Ответ о договоре может потребовать сведения из актов и платежей.
Поиск наиболее похожих фрагментов по тексту может пропустить связанный документ.

## Решение

PostgreSQL используется для поиска по имени файла и явному номеру договора,
Qdrant - для семантического поиска. В режиме GraphRAG Neo4j дополняет
результаты по связям `Document → Chunk → Contract`.
Ключ договора включает номер, дату и ИНН. Связь создаётся по извлечённым
реквизитам с подтверждающими цитатами. Поиск по конкретному имени файла
ограничивается этим файлом. Права и готовность источников проверяются в PostgreSQL.

## Альтернативы и причина выбора

Связь по договору можно хранить в SQL, а векторный поиск - в pgvector.
Это сократило бы число хранилищ. Qdrant и Neo4j выбраны, чтобы проверить
сочетание векторного поиска и обхода явных связей между документами,
а также показывать путь, по которому найден дополнительный источник.
Преимущество этого набора над SQL на текущем объёме данных не установлено.

## Допущения и ограничения

Граф описывает связи документов через договор. Качество связей зависит
от распознанных реквизитов. Совпадения номеров и ошибки OCR могут исказить поиск.
Количество фрагментов и размер контекста ограничены. Два отдельных индекса
добавляют операции записи и риск рассогласования с PostgreSQL.
